## 1. What changed

Outbound opcode translation (logical/core SMSG id -> 1.60.1.70790 client wire id) uses **only** the ProtocolAdapter dense table.
`ClassicOpcodes::TranslateServerOpcode` is gone from the send critical path (`SendPacket`, `WritePacketToBuffer`, `CompressPacket`).

## 2. Table choice: reuse, no duplicate

Blocco1 already loads `AdapterOpcodeTable::smsgLogicalToWire` at boot: a `DenseOpcodeMap` (fixed `std::array` storage, GroupSpan[256] + 4096 slots,
O(1) = 1 range check + 2 array reads + valid bit, zero heap) with all 1410 SMSG rows of `opcodes.json` (generated by
`gen_opcode_table.py`, a faithful port of `TranslateServerOpcode` for build 70790). Blocco4 **exposes that array as `SmsgAdapterTable()`**
and uses it for the send path instead of allocating a second ~50 KB copy (stability + simplicity: one source of truth, one SHA-256-verified load).

## 3. Send path

1. `SendPacket`: `IsServerOpcodeBlocked` (unchanged policy) -> **`TranslateOutbound(logical, wire)`**; false = packet NOT queued -> stub payload (unchanged) -> enqueue.
2. `WritePacketToBuffer`: `PeekOutboundWire` (no counters). Miss is unreachable (table immutable after boot); if it happens nothing is written.
3. Compressed envelope: wire of `SMSG_COMPRESSED_PACKET` from `PeekOutboundWire`; if unmapped the packet is written uncompressed (valid framing). `CompressPacket` receives the adapter wire id from the caller.

## 4. Unmapped logical opcode policy

Legacy `TranslateServerOpcode` returned the core id unchanged for ids outside the retail server groups (a bogus wire id on the client).
Adapter policy: **do not send**. Outbound unknown counter + rate-limited `TC_LOG_ERROR("network.opcode", "... smsg_logical=0x...")` using
`unknown_policy.json` (10000 ms / threshold 50 / max 1 ERROR per window) on a **separate outbound window** (inbound budget and Blocco3 behaviour unchanged).
Never the raw logical id, never the legacy translator. Table not loaded -> fail closed: nothing is sent, no counters, no log (boot already logged FATAL).

## 5. Boot lines

- `Aeternum ProtocolAdapter: ACTIVE profile ... (dispatch=adapter ProtocolAdapter)` (inbound, unchanged)
- `Aeternum ProtocolAdapter: SMSG outbound ACTIVE SmsgAdapterTable entries=N slots=N legacy_parity=X/N (send=adapter SmsgAdapterTable)`
- Boot-only parity audit: every SmsgAdapterTable row is compared once with `ClassicOpcodes::TranslateServerOpcode` under the live config.
  Mismatches -> `TC_LOG_ERROR` (max 10 detail lines + summary). This is not on the send path and is not a fallback.

## 6. Remaining ClassicOpcodes on the send side

`IsServerOpcodeBlocked` (3 blocked SMSG) and `GetServerStubPayload` (placeholder payloads) are send **policy**, not translation; unchanged.
`TranslateServerOpcode` remains defined in `ClassicOpcodes.cpp` and is called only by the boot parity audit.

Revert the Blocco4 local commit (outbound returns to `TranslateServerOpcode`). No runtime toggle.
